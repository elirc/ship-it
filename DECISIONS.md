# Engineering decisions

- **25 complete exercises; 40 roadmap entries.** The original 19 seed exercises are joined by six executable engineering labs covering debugging, regression-test design, retries, race conditions, idempotency, and concurrency. Later TypeScript, Node, authentication, CI, and deployment tickets remain explicitly upcoming.
- **React preview is explicit.** Linear sprint progression stops at unauthored content. The labeled React lab opens its first ticket and unlocks the next three linearly without claiming the intervening bosses were completed.
- **Vanilla DOM uses a real sandbox document.** DOM exercises use the iframe runner alongside React. A Web Worker has no DOM; providing real DOM semantics is more useful than inventing an incomplete element mock. Pure JS and asynchronous exercises use a worker.
- **No host-thread learner execution.** Compilation and formatting happen in workers. Pure code runs in an isolated worker; React/DOM code runs in a separate opaque-origin iframe document. DOM timers and rendering require that document’s event loop. Browsers may share processes between frames: the wall-clock parent timeout cannot interrupt every possible adversarial native blocking operation in a frame. Compiler-injected loop guards handle normal accidental loops; this is not an OS-level security boundary for hostile programs.
- **CSP blocks the network, beyond replacing fetch.** Worker runtimes are created inside the restricted iframe so blob workers inherit its policy. Remote dynamic imports, resource elements, and alternative network APIs cannot bypass a simple fetch replacement. The local app still fetches its own prebuilt runtime assets before learner execution.
- **A small shared test DSL instead of Vitest in the browser.** The harness supports named async tests, deep equality, identity, truthiness, throw/reject assertions, bonus flags, console capture, and relative module imports. Vitest tests the app and harness. Future type-level tickets must add a proper compile-time verifier before becoming playable; transpilation alone does not prove types or reject `any`.
- **In-memory API injection.** Seeded network exercises receive mock transports in their tests. Node/Express/SQLite/auth exercises are clearly coming soon. A production Node runtime and cryptography are not simulated or misleadingly represented as complete.
- **Local, inspectable progress.** Zustand persist uses `ship-it.progress.v1`. Imports are size-limited, shape-checked, path-restricted, and reward totals are recalculated from known test names. Progress and tests are not tamper-resistant: this is an offline personal learning tool.
- **References after passing.** The domain stores reference code client-side for build validation and the requested review diff. UI access is gated by a passing snapshot. This reconciles the request to avoid showing raw answers with the required post-pass side-by-side reference review.
- **Help is not penalized.** Hints retain three levels and usage records but have no XP cost. Existing rewards recalculate on load or import. The growth plan emphasizes independent recall and explanations instead of avoiding assistance.
- **Rewards reflect learning activity, not seniority.** A considered-refactor badge requires changed passing code plus recorded explanation, evidence, and trade-off; it does not grade the prose. Ten passes count regardless of hints. Three due recall sessions earn the recall badge. Old line-count, no-hint, and speed badge IDs are retired rather than relabeled as new evidence. Other previously earned badges are preserved.
- **Separate recall state.** Each ticket can hold an active recall draft, attempt count, and pass status without changing normal code, attempts, earned XP, or the passing snapshot. Successful due sessions schedule the next interval; repeated passes, early practice, assisted sessions, and invalid result sets cannot advance it. One calendar-day interval means the same local time on the next day, respecting daylight-saving changes.
- **Evidence is inspectable and honestly labeled.** Notes, fieldwork evidence, and recall state are included in the existing version-1 backup with backward-compatible defaults and validation. Text lengths and recall file paths are bounded. The app does not infer quality from essay length or certify job readiness from exercise completion.
- **Real-world transfer remains human work.** Senior-oriented briefs require a repository, design decisions, operational evidence, and feedback from other people. They have concrete deliverables and saved notes, but no fake automated completion check. The 1/3/7/21-day schedule is a simple product choice, not a scientifically optimal interval claim.
- **Local assets and progressive editor loading.** Monaco, its language workers, React sandbox assets, TypeScript, and Prettier are bundled locally. An immediately usable, highlighted text field upgrades to Monaco on focus or pointer entry, preserving drafts and selection while the module loads. Reading tickets and navigating the app do not require loading a language service. Review diffs load Monaco immediately. Worker payloads stay off the host thread. Measure performance on the production preview for a target device.
